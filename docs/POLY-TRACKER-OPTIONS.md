# Polyphonic tracking for guitar and bass

## Start from measured limits

The existing streaming filter bank gives the host prototype a useful comparison point. It updates every 64 input samples at 44.1 kHz (1.45 ms). That is the update interval. Actual note acquisition also includes filter settling and confirmation. The default build examines 15 ERB bands up to about 790 Hz, with candidate fundamentals limited to 60–1,400 Hz. The 60 Hz cutoff excludes standard bass E1 (41.20 Hz) and B0 (30.87 Hz), although higher harmonics of those notes can still appear as wrong candidates. Lowering the candidate cutoff must be evaluated together with detector evidence below 60 Hz, against false subharmonics on guitar. Check tunings and boundaries as part of the comparison. [Engine tracker](../engine/px_track.h) · [Existing GuitarSet baseline](POLY-SYNTH-DESIGN.md#check-candidate-quality-before-tuning-the-allocator)

The baseline detected both notes in 15.2% of settled dyad frames and the lowest note in 54.8% of those frames. In single-note frames it generated an extra candidate 42.8% of the time. Any replacement needs to improve both sides so a quiet second note can enter without generating extra oscillator voices on an ordinary single-note riff.

## Implementations to compare

| Candidate | Use in OpenPocket | Conditions |
|---|---|---|
| **Current ERB and Klapuri-style salience** | First embedded candidate. Compare the default with more of the existing ERB bands, additional low bands, and harmonic cancellation that retains shared evidence. Use a bounded joint fit of the strongest few candidates to test whether shared energy belongs to a dyad. | Keep this opt-in during experiments so mono users keep their existing response. A larger bank increases sample-rate work, while a larger candidate set increases frame-rate work. The joint fit should score one- and two-note hypotheses explicitly rather than always filling both slots. [Klapuri's iterative and joint methods](https://labrosa.ee.columbia.edu/~dpwe/papers/Klap06-multif0.pdf) |
| **Fast RTFI and guitar resonator implementations** | Compare on the host with the same audio and annotations. The 2009 algorithm uses streaming complex resonators, harmonic grouping and tests for false candidates. The `pdct_lib/Pdct` directory contains the GPLv3 C++ detector, and a separate GPLv3 Rust library offers a simpler semitone resonator bank with Cycfi Q for its mono technique path. | Extract algorithm timing from desktop audio and UI dependencies. The Rust project's nominal 512-sample frame duration is about 11.6 ms, while its default `alpha=0.999` corresponds to about 22.7 ms resonator amplitude decay at 44.1 kHz. These values describe different things, and neither establishes an observed onset delay. Test close notes, shared harmonics, bends, pitch ranges and bass separately. [Zhou et al.](https://doi.org/10.1155/2009/729494) · [C++ detector source](https://github.com/luciamarock/Polyphonic-Pitch-Detector-for-guitars/tree/master/pdct_lib/Pdct) · [Rust resonator source](https://github.com/santzit/guitar-pitch-detection-/blob/main/src/resonator.rs) · [Rust project license](https://github.com/santzit/guitar-pitch-detection-) |
| **Essentia MultiPitchKlapuri** | Independent host reference for spectral whitening and Klapuri harmonic salience. Use default settings as one point, then replay past-only frames with shorter windows and a separate timestamp for when candidates become available. | The default 2,048-sample frame and 128-sample hop at 44.1 kHz correspond to 46.4 ms and 2.9 ms respectively. The batch output needs measured streaming timestamps for a fair latency comparison. Essentia's upstream license is AGPLv3, so use upstream as a standalone host tool and check licensing separately before proposing any embedded code. [Essentia algorithm parameters](https://essentia.upf.edu/reference/std_MultiPitchKlapuri.html) · [Essentia source and license](https://github.com/MTG/essentia) |
| **Basic Pitch and FretNet** | Host accuracy references. Basic Pitch returns notes, onsets and pitch contours. FretNet gives a guitar-specific reference for continuous contours and preserving bends. They can distinguish problems with our candidate detector from problems in annotations or voice assignment. | Basic Pitch's stock inference uses overlapped audio windows and is a batch reference. FretNet's research implementation has MIT-licensed code. Check any model weights separately before redistribution. A separate streaming browser implementation, PitchPlease, reports 23 ms of lookahead before other delays and is useful as a host latency reference. Its SIMD host measurements do not establish AC791N cost. [Basic Pitch inference](https://github.com/spotify/basic-pitch/blob/main/basic_pitch/inference.py) · [Apache 2.0 license](https://github.com/spotify/basic-pitch/blob/main/LICENSE) · [FretNet implementation](https://github.com/cwitkowitz/guitar-transcription-continuous) · [PitchPlease source and benchmarks](https://github.com/markusstrasser/pitchplease) |
| **KISS FFT with a past-only spectrum** | If the IIR front end limits accuracy, compare it with a bounded real FFT and the same candidate scorer. KISS FFT offers reusable real, fixed-point and floating-point C kernels under BSD-3-Clause. OpenPocket also has a 128-sample real FFT used by the cab convolution. Verify which implementation costs less before adding a firmware dependency. | At 11.025 kHz, 256 and 512 sample windows cover 23.2 and 46.4 ms. Interpolation can refine an isolated peak, but zero padding cannot resolve two low overlapping peaks. Score staggered attacks and quick mutes as well as held notes. [KISS FFT](https://github.com/mborgerding/kissfft) · [OpenPocket cab FFT](../engine/px_dsp.c) |

Cycfi Q or Aubio YIN are useful bass-note sanity checks on genuinely monophonic passages. A single estimated period cannot establish the lowest *actual* note in a chord. Power chords in particular can yield a strong shared subharmonic that no string is playing. [Aubio pitch API](https://github.com/aubio/aubio/blob/master/src/pitch/pitch.h)

## Comparison design

1. Feed every detector the same single pickup audio and use the same annotated scoring. Separate raw candidate precision and recall from the results of the two-voice allocator. Score one note, a dyad, and three or more notes separately. Use one-to-one matching within 50 cents and record both-note accuracy, lowest-note accuracy, false octaves and subharmonics, and extra candidates on single notes. Report release latency and missed notes next to the successful onset latency distribution. Score against the time when a result is available, including analysis, confirmation and any lookahead. [GuitarSet recordings and annotations](https://zenodo.org/records/3371780)
2. Add controlled real dry recordings of bass B0/E1 and guitar E2, quiet fingerstyle and palm mutes, and separate-string takes mixed at known times and levels. Include close dyads, octaves, bends, and a held note under a quieter onset or repick. Use different recordings for coefficient tuning and the comparison. An octave fundamental can overlap another string's harmonic exactly, so the result is allowed to retain one confident voice while evidence for the second is ambiguous.
3. Measure a compact configuration and a larger poly-only configuration on the pedal. Use the full poly effect alone and with Smart Gate. Log worst callback time, overshoot counts or dropouts, added RAM and flash, and input-to-audible-note delay. Compare candidate selection cost during a full strum against silence. Host measurements can screen alternatives before these hardware checks.
4. Run bass-follow and independent synth voices as separate acceptance checks. Bass-follow needs a stable lowest note and clean recovery on a wrong estimate. The synth needs per-note onset, repick and mute evidence, plus useful lower registers and acceptable timing. Advance the detector and effect separately so a good oscillator cannot disguise wrong notes.
