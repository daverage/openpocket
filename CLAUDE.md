This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

OpenPocket is from-scratch guitar multi-effects firmware for the Donner Pocket X and M-VAVE BlackBox (JieLi AC791N, two cores, float FPU), plus a browser installer and preset editor (`docs/`, served on GitHub Pages). See also `AGENTS.md` and the project skills in `.claude/skills/` (`verify`, `openpocket-toolchain`, `openpocket-simulator`, `openpocket-flash`, `openpocket-rescue`, `verify-pedal`).

## Commands

Every `make` target is a thin wrapper over `node tools/op.mjs <command>` (Node 18+); the Docker command lines live only in `tools/op.mjs`. Windows uses the `.bat` files, which call the same thing.

- `make doctor` — check Node, Docker, the build image
- `make build` / `make package` — firmware in the pinned `linux/amd64` container (JieLi clang exists only for x86-64 Linux; emulated on Apple silicon). Outputs `firmware/openpocket.bin`, `docs/firmware/{PocketX,BlackBox}_9NN.fwsc`, `manifest.json`; `package` adds `build/SHA256SUMS`. The build is deterministic — compare SHA256SUMS when changing pins.
- `make NATIVE=1 build` — skip Docker, use a toolchain from `firmware/setup.sh` (`~/.jieli`)
- `make ble` — the separate Bluetooth MIDI test image (`OP_BLE=1`), own output dirs
- `make test` — `tests/run_tests.sh`; runs on the host with only a C compiler, Node and Python 3 (no Docker, no pedal). NAM comparison needs NumPy; page tests need Playwright (`npm i playwright && npx playwright install chromium`); both are skipped silently otherwise. Pass an official `PocketX_016.fwsc` as the argument to also run the byte-for-byte package rebuild test.
- `make sim` — simulated pedal on `http://127.0.0.1:8766/` (real screen, editor protocol, preset store, HTTP API; see `docs/SIMULATOR.md`)
- `make wasm` — rebuild `tools/sim/px_engine.wasm` (committed). **Any change to `engine/px_dsp.c`, `engine/px_wasm.c` or `firmware/px_math.c` requires `make wasm`**, otherwise `tests/test_audio.mjs` fails on the stored source hash (`px_engine.wasm.sources`).
- `make render IN=guitar.wav [OUT=out.wav] [PRESET=1]` — a WAV through the engine on the host
- `tests/equiv.sh REF` — is this tree's engine bit-identical to commit REF's (852 hashed runs). Use for refactors/optimisations that must not change sound.

Running a single test: there is no test framework; each test is a standalone C program or Node/Python script. Copy its line from `tests/run_tests.sh`, e.g.
```
cc -O2 -Iengine tests/engine/sweep2.c engine/px_dsp.c firmware/px_math.c -lm -o build/sweep && build/sweep
node tests/test_editor.mjs        # needs build/edsim built first (see run_tests.sh)
python3 tests/test_post5.py
```
Several Node tests depend on simulators compiled earlier in the script (`build/devsim`, `build/edsim`, `build/edsim_diag`).

Flashing real hardware (`make flash`, `make rescue-write`): always `--dry-run` first, and never write to a pedal without the user's explicit instruction — see `.claude/skills/openpocket-flash/SKILL.md`.

## Architecture

**Engine (`engine/`)** — portable float C, shared verbatim by the pedal, the host tests, `make render` and the WebAssembly simulator. `px_dsp.h` defines the preset model the UI and engine share: 12 blocks (`PX_B_*`, SYN appended last so older presets keep indices), each with a TYPE, ON/OFF and 5 params 0..100, plus a per-preset block `order[]`. DRIVE+AMP share one oversampled (×4) section when adjacent. `px_nam.c` is the Neural Amp Modeler A2-Lite network in fixed point, with hand-written vector routines (`PXN_HAND`; `PXN_EMUVEC` emulates the vector unit on the host); `px_nam_factory.h` is generated by `tools/mk_nam_factory.py`, not hand-edited. The engine is split into pipeline stages (`PX_PART_PRE / NAM / POST`) so CPU0 and CPU1 can run them in parallel, one block later than the single-core path (`tests/engine/pipe_test.c` checks that equivalence).

Numerical rule: the pedal has no hardware sqrt and does not fuse multiply-add. The engine's libm is `firmware/px_math.c`, and bit-exact comparisons build with `-fno-builtin -ffp-contract=off`.

**Firmware (`firmware/`)** — a single translation unit: `openpocket.c` `#include`s the header-only modules (`px_audio.h` I2S + DSP scheduling and the overload-to-BYPASS safeguard, `ui.h` screen/pages, `px_store.h` power-cut-safe preset flash store, `px_editor.h` web-editor SysEx protocol, `px_midi.h`/`px_midi_io.h` MIDI, `px_usb.h` USB-MIDI + update entry, `px_uaudio.h` USB audio, `px_models.h`/`px_irs.h` user NAM models and cabinet IRs in flash, `px_lights.h`/`px_leds.h` button LEDs). Because they are headers, the host tests compile the same headers directly against simulated flash/hardware (`tests/test_store.c`, `tests/edsim.c`, `tests/uisim.c`, `tests/midisim.c`, …). `bsp/` is felucca-bsp (MPL-2.0); `sdk/` holds JieLi SDK pieces (I2S driver from bitcode). `app.ld` lays out RAM-resident code (`.rt`), noinit boot guard and the stack-guard check; the build refuses to link if the guard is violated.

**Update path** — `loader/` is the update loader that runs from RAM and writes the app area (`ldr_core.c`). `tools/pxpkg.py` (and `docs/pxpkg.js` in the browser) packages app + loader into `.fwsc`. `docs/pxota.js` is the update protocol, shared by the web installer (`docs/index.html`) and the CLI flasher (`tools/flash.mjs`). Tests run these against `tests/devsim.c`, a simulated pedal executing the real `ota.c`/`ldr_core.c` on simulated flash.

**Web (`docs/`)** — plain JS, no bundler. Installer: `index.html` + `pxota.js`/`pxpkg.js`. Editor: `editor.html` + `ed*.js` UI modules over `pxedit.js` (protocol, `docs/EDITOR-PROTOCOL.md`), `pxmidi.js` (CC map, must match `docs/MIDI.md`), `pxlib.js`/`pxnam.js`/`pxir.js` (model/IR library), `pxt3k.js` (TONE3000).

**Host tooling (`tools/`)** — `op.mjs` (entry point for everything), `sim.mjs` + `tools/sim/` (hosted simulator), `uboot_rescue.py` (BlackBox rescue over the chip's UBOOT mode), and Python model-fitting scripts (`fit_amp.py`, `fit_drive.py`, `fit_cab.py`, `train_a2.py`) that produce engine constants offline.

## Conventions

- Firmware versions (`vNN`) are documented in `docs/WHATS-NEW-v*.md`; code comments tag changes with the version that introduced them. User-facing model/control docs live in `docs/SOUNDS-AND-CONTROLS.md`; chip knowledge in `docs/HARDWARE-HANDBOOK.md`.
- No build outputs are committed, except `tools/sim/px_engine.wasm` (+ its `.sources` hash).
- `PUBLISH-*.bat` are the maintainer's Windows release tools; `main` on GitHub is overwritten from the local folder on publish.

## Bluetooth (not in the release; research on branch `bluetooth`)

- The release firmware has no radio. The BLE test image (`OP_BLE=1`, `firmware/ble/`, `docs/BLE-TEST.md`) advertises and hears scanners but, at v76, **crashes or hangs on most boots** with the cause still unknown. Read [docs/research/BLUETOOTH-RADIO-FINDINGS.md](docs/research/BLUETOOTH-RADIO-FINDINGS.md) first: it has the experiment log, what is ruled out (do not repeat it) and the next tests in order. The plan and rules for the work are in `docs/research/BLUETOOTH-EDITOR-PROMPT.md`.
- The page side is finished and host-tested: `docs/pxble.js` (a Web MIDI-shaped access over a GATT service of our own, SysEx framed by F0..F7) and `tests/test_pxble.mjs`. It is not yet wired into `editor.js`. Replies reach 851 bytes, so the pedal side must chunk its notifications; the negotiated MTU decides how slow the first catalogue read is.
- Build the BLE image with `docker run --rm --platform linux/amd64 --user $(id -u):$(id -g) -e HOME=/tmp -e OP_BLE=1 [-e OP_BLE_NORADIO=1] [-e OP_BLE_EARLY=0] [-e OP_BLE_RUNS=0] -v "$PWD":/src -w /src openpocket-build sh firmware/build.sh`. `node tools/op.mjs ble` does not pass those variables into the container. Output: `build/ble/`.
- Pedal rules: `flash --dry-run` first; flash a BLE image only on the user's word for that image; afterwards restore `docs/firmware/BlackBox_<ver>.fwsc`. After a failed boot the next start is safe mode (effects off) once; power-cycle to clear it. Never save presets from a test.
- Reading a crash on the BLE image: `node tools/op.mjs log` (the `regs`, `etm`, `radio`, `code` and `stall` lines come from DIAG, BLE image only), then look the PCs up in `firmware/build-ble/symbols.txt`. Disassemble with `objdump --mcpu=r3`: the default shows the FPU instructions as "unknown". `EMU`/`DBG` bits: `docs/HARDWARE-HANDBOOK.md`. The log is readable after a reset, not after a power cycle (`.noinit` RAM).
- `firmware/bsp/chip/fm1_irq.h` carries an OpenPocket addition (`fm1_crash_t.code[8]`) that affects every build, not only the BLE image.
- `build/` can hold Linux binaries from earlier container builds; on a Mac they fail with `ENOEXEC` (for example `build/edsim`, `build/devsim`). Rebuild the one a test needs with the `$CC` line in `tests/run_tests.sh`.

## Build and verify

- Follow [docs/BUILDING.md](docs/BUILDING.md) for toolchain setup and packaging. `make doctor` checks prerequisites, and `make package` builds the firmware and installer packages.
- Run `make test` for host verification. The suite covers DSP, preset storage, and the installer and editor against a simulated pedal. See the [README test section](README.md#test-no-pedal-needed) for the optional factory firmware input.
- Use `make sim` to exercise the pedal UI, web installer, preset editor, or audio interactively without hardware. See [docs/SIMULATOR.md](docs/SIMULATOR.md).
